클라이언트(`Client.exe`) 요구사항은 `요구사항_및_개발진행.md`를 참고한다.

## 1. 목적

- Windows 클라이언트가 약속된 파일만 안정적으로 다운로드할 수 있도록  
  Linux SFTP 서버의 **계정·권한·Host Key·네트워크·모니터링** 기준을 정의한다.
- PoC 단계에서도 운영과 동일한 보안 원칙(Host Key 검증, 최소 권한)을 적용한다.

## 2. 서버 전제 조건

| 항목 | 요구 |
|------|------|
| OS | Linux (2021년 전후 구축 서버) |
| SSH/SFTP | OpenSSH `sshd` 제공 SFTP |
| 포트 | 기본 22 (변경 시 클라이언트 `Port`와 동일해야 함) |
| 인증 | PoC: **비밀번호 인증** (ID/PW) |
| Host Key | **RSA 또는 ECDSA** 필수 제공  
  (클라이언트 WinCNG는 Ed25519 host key 미지원) |
| 방화벽 | 클라이언트 → 서버 TCP(포트) 허용 |

## 3. 기본 sshd 설정 권고

설정 파일 예: `/etc/ssh/sshd_config`  
(환경에 따라 `sshd_config.d/*.conf` 분리 가능)

### 3.1 필수/권고 항목

```text
Port 22
Protocol 2

# HostKey — RSA/ECDSA 중 최소 1개 이상 활성화 권장
HostKey /etc/ssh/ssh_host_rsa_key
HostKey /etc/ssh/ssh_host_ecdsa_key
# HostKey /etc/ssh/ssh_host_ed25519_key   # 있어도 됨 (클라이언트가 다른 키를 협상)

PubkeyAuthentication yes
PasswordAuthentication yes          # PoC. 운영에서는 키 인증 전환 검토
PermitEmptyPasswords no
ChallengeResponseAuthentication no
UsePAM yes

# 루트 직접 로그인 금지 권고
PermitRootLogin no

# SFTP만 허용하는 전용 계정 권고 (아래 Chroot 예시 참고)
Subsystem sftp internal-sftp
```

변경 후:

```bash
sudo sshd -t
sudo systemctl reload sshd
# 또는
sudo service ssh reload
```

### 3.2 SFTP 전용 계정 + Chroot (권고)

다운로드 전용 계정은 쉘 로그인보다 **SFTP only + Chroot**를 권장한다.

```text
Match User sftpdownload
    ChrootDirectory /data/sftp/%u
    ForceCommand internal-sftp
    AllowTcpForwarding no
    X11Forwarding no
    PasswordAuthentication yes
```

디렉터리 예:

```text
/data/sftp/sftpdownload/          # root:root, 755
/data/sftp/sftpdownload/data/     # sftpdownload:sftpdownload, 755
/data/sftp/sftpdownload/data/*.dat
```

> Chroot 사용 시 클라이언트 `RemoteFile` 경로는 chroot 기준 상대경로가 된다.  
> 예: 실제 `/data/sftp/sftpdownload/data/test.dat` → RemoteFile=`/data/test.dat`

Chroot를 쓰지 않는 단순 PoC라면 RemoteFile에 서버 절대경로를 그대로 넣는다.  
예: `/data/test.dat`

## 4. Host Fingerprint 운용

클라이언트는 `config.ini`의 `HostFingerprint`와 서버 Host Key SHA256을 **반드시** 비교한다.  
미등록·불일치 시 **연결하지 않는다(또는 handshake 후 즉시 종료)**.

### 4.1 Fingerprint 확인 명령

```bash
# ECDSA (권장 — 클라이언트 ECDSA 지원)
ssh-keygen -lf /etc/ssh/ssh_host_ecdsa_key.pub -E sha256

# RSA
ssh-keygen -lf /etc/ssh/ssh_host_rsa_key.pub -E sha256
```

출력 예:

```text
256 SHA256:AbCdEf... root@hostname (ECDSA)
```

클라이언트에는 아래 형식만 넣는다.

```ini
HostFingerprint=SHA256:AbCdEf...
```

### 4.2 운용 규칙

| 상황 | 조치 |
|------|------|
| 서버 재설치 / Host Key 재생성 | 새 fingerprint를 모든 클라이언트 `config.ini`에 배포 |
| fingerprint 교체 전후 | 불일치로 전량 실패 → **사전 공지 필수** |
| 임시로 검증 끄기 | **금지** (클라이언트도 trust-all 미구현) |
| Ed25519만 남는 구성 | **금지** — RSA 또는 ECDSA host key 유지 |

### 4.3 실제 협상되는 Host Key

OpenSSH는 클라이언트/서버 알고리즘 협상 결과에 따라  
RSA/ECDSA/Ed25519 중 하나가 선택될 수 있다.  
클라이언트가 Ed25519를 못 쓰는 경우, 서버가 RSA/ECDSA를 제공하면 해당 키로 협상된다.

운영자는 다음을 확인한다.

```bash
ls -l /etc/ssh/ssh_host_*_key.pub
sshd -T | grep -i hostkey
```

## 5. 계정 / 권한 / 파일 배치

### 5.1 계정

| 항목 | 요구 |
|------|------|
| 용도 | 다운로드 전용 (가능하면 업로드 불필요) |
| 비밀번호 | 복잡 규칙 준수, 정기 변경 정책 |
| sudo | 불필요 — 부여하지 않음 |
| 홈/데이터 | 약속된 디렉터리만 접근 |

### 5.2 파일

| 항목 | 요구 |
|------|------|
| 개수 | 클라이언트당 사전 합의 1~20개 |
| 경로 | `config.ini`의 RemoteFile과 **완전 일치** |
| 형식 | 일반 파일 (디렉터리/특수파일 불가) |
| 권한 | SFTP 계정에 **읽기** 가능 |
| 원자적 배치 | 전송 중 파일은 temp → rename 권장 |

원자적 배치 예:

```bash
cp source.dat /data/test.dat.part
mv /data/test.dat.part /data/test.dat
```

### 5.3 디스크 / 용량

- 다운로드 대상 파일 보관 공간 여유 모니터링
- inode/용량 임계치 알람(예: 80%/90%)

## 6. 네트워크 / 방화벽

| 항목 | 요구 |
|------|------|
| 허용 방향 | 클라이언트 → 서버 TCP `Port` |
| 소스 IP | 가능하면 고객사/현장 IP만 allow |
| NAT | 공인/사설 주소와 `config.ini` Host 일치 확인 |
| DNS | Host에 이름 사용 시 클라이언트 DNS 해석 가능해야 함 |
| 타임아웃 | 장시간 유휴 시 방화벽 idle timeout 고려 |

방화벽 예 (firewalld):

```bash
sudo firewall-cmd --permanent --add-service=ssh
# 또는 특정 포트/소스
sudo firewall-cmd --reload
```

## 7. 로깅 / 감사

### 7.1 서버 로그

- `/var/log/auth.log` 또는 `/var/log/secure`
- 실패 로그인, 성공 로그인, 비정상 접속 주기 점검

### 7.2 권고 모니터링 항목

| 항목 | 기준 예 |
|------|---------|
| 인증 실패 급증 | 브루트포스 의심 → fail2ban 등 |
| 디스크 사용량 | 임계 초과 시 알람 |
| sshd 프로세스/서비스 | down 시 알람 |
| Host Key 변경 | 변경 시 변경관리 티켓 필수 |

### 7.3 클라이언트 연계

클라이언트 콘솔에 남는 오류와 서버 auth 로그를 대조한다.

| 클라이언트 메시지 | 서버 측 점검 |
|-------------------|--------------|
| 서버 연결 실패 | 방화벽/sshd/IP/Port |
| Host Key 불일치 | fingerprint 배포 상태, Host Key 재생성 여부 |
| 로그인 실패 | 계정/비밀번호/PasswordAuthentication |
| RemoteFile 없음 | 경로·권한·Chroot 기준 경로 |

## 10. 보안 권고 (PoC 이후 운영 고도화)

PoC는 ID/PW를 `config.ini`에 평문 보관한다. 운영 전환 시 다음을 권장한다.

1. 공개키 인증으로 전환 (비밀번호 인증 축소/비활성)
2. 클라이언트 설정 파일 암호화 또는 OS ACL 최소화
3. 계정별 IP 제한 / VPN 경유
4. 파일별 읽기 전용 + 디렉터리 분리
5. 접속/다운로드 감사 로그 SIEM 연동
